# Design Doc ディレクトリ作業ルール

このディレクトリ（`docs/engineering/design-docs/`）で Design Doc を作成・編集する際のガイド。

## 基本原則

- **README に従う**: 作成・更新するときは、まず [README.md](./README.md) を読み、採番、ステータス、運用ルールに従う。

## 書く内容・書かない内容

- **書く**: 背景と目的、満たす要件、設計上の意思決定とその根拠、却下した代替案。
- **書かない**: 「セキュリティリスクがある」のような汎用リスクや定型文。書くなら具体的に。
- **書かない**: 個別の実装手順やチケット分割。実装ロードマップはフェーズ単位の方針までとし、詳細は Issue 側で管理。

## レビュー時の扱い

- 汎用の文書ガイド（「コードから推論できる情報は書かない」など）を機械的に適用しない。実装前の文書であり、実装の存在を前提とした指摘は当たらない。

## 関連ドキュメント

- [ADR](../adr/): 横断的なアーキテクチャ判断の記録先。Design Doc 内で生まれた横断的な決定は ADR に切り出してリンクする。

## 編集時のチェック

- テンプレート冒頭・各節の `<!-- ... -->` コメントは、最終成果物では削除すること（記法ガイドのため）。
