# Close Issue

作業内容と結果は会話で把握しているものを使い、**read-issue** での読み直しはしない。不明な事実だけを PR やコミットで確かめる。

## 本文を整える

対象 Issue の親子関係と本文のリンクから、紐づく Epic を確認する。Sub Issue なら親 Issue を確認し、親 Epic も更新対象に含める。

対象 Issue と Epic は更新直前に本文を取得し、チェックの状態と事実が変わった箇所だけを更新する。他者の編集を上書きせず、背景や要望・経緯を残す。

- 達成した項目のチェックボックスにチェックを付ける。途中で取りやめた作業は達成に数えない。
- 作業の途中で変わった方針・範囲・手順など、古くなった記載を実際の結果に合わせて書き換える。別の作業に置き換えた項目は、実際に行った内容に書き換えてチェックを付ける。他者が書いた記載は消さずに、現状を注記する。
- 未達の項目は消さず、チェックも付けない。対応しなかった理由か移管先を書く。

Epic では対象 Issue に関するチェックボックス・進捗・方針・残作業を更新する。対象 Issue の完了だけで、他の Sub Issue や Epic 全体を完了扱いにしない。

## クローズする

GitHub のクローズ理由 (completed / not planned / duplicate) は、実際の結果に合うものを選ぶ。

未達・対応見送り・移管・重複など、整えた本文とクローズ理由だけでは閉じる理由が分からないときだけ、本文と重複しない理由を端的にコメントする。完了条件をすべて満たして閉じるときはコメントしない。

完了条件が求める手順や確認先の記録は、クローズのコメントではなく、作業記録のコメントか本文に置く。

クローズ後に対象 Issue と Epic の本文を確認し、クローズ結果と食い違う記載が残っていれば再更新する。Epic 自体のクローズはこの手順には含めない。

## 報告

対象 Issue と更新した Epic へのリンク、それぞれの本文の変更点を示す。クローズのコメントを書いたときは、それも示す。
