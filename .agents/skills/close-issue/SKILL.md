# Close Issue

作業内容と結果は会話から把握する。read-issue で読み直さず、不明な事実だけを PR やコミットで確かめる。

## 1. Issue と Epic の本文を更新する

紐づく Epic は GitHub の親子関係と本文のリンクの両方で確認する。Sub Issue の場合は親 Issue を確認し、親 Epic も更新する。

更新直前に本文を取得し、チェック状態と事実が変わった箇所だけを直す。背景・要望・経緯と他者の編集を残す。他者の記述が古くなった箇所には現状を注記する。

- 達成した項目にチェックを付ける。方針・範囲・手順の変更を反映し、別の作業で達成した項目は実施内容に書き換える。
- 取りやめた作業を含め、未達の項目は未チェックのまま残し、理由か移管先を書く。引き続き対応が必要な項目には移管先を書く。移管先がなければ報告の冒頭で伝える。

Epic では対象 Issue に関するチェック状態・進捗・方針・残作業を更新する。他の Sub Issue や Epic 全体の完了は対象 Issue の完了だけで判断しない。

## 2. 対象 Issue をクローズする

結果に合うクローズ理由（completed / not planned / duplicate）を選ぶ。Epic も、その完了条件を満たしていれば同じ手順で閉じる。対象 Issue の完了だけを理由に閉じない。

完了条件をすべて満たした場合はクローズコメントを付けない。未達・見送り・移管・重複などで、更新した本文とクローズ理由だけでは事情が伝わらない場合に限り、不足する理由を短くコメントする。完了条件で求められた手順や確認先は本文か作業記録のコメントに残す。

## 3. クローズ結果を確認して報告する

対象 Issue と Epic の本文を再取得し、クローズ結果と食い違う記載を直す。その後、対象 Issue と更新した Epic のリンク、それぞれの本文の変更点、クローズ時に付けたコメント（あれば）を報告する。
