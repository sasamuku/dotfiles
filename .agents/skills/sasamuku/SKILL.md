# sasamuku

## 進め方

1. 依頼を下の索引と照らし合わせ、該当するプレイブックを `playbooks/<name>.md` で開く。
2. todo リストを作り、プレイブックの手順をそのまま写す。todo リストはハーネスの計画ツールで作る (Codex は `update_plan`、Claude Code は `TodoWrite` など)。使えるツールが無ければ、返信の中にリストを書き、手順を終えるたびに更新する。
3. やらない手順も消さずに残し、`skip: <理由>` を付ける。
4. 手順を順に実行し、プレイブック末尾の「**返信:**」に書かれた内容で返す。

該当するプレイブックが無いときは、その旨を一言書いてから通常どおり進める。

## 自律性

- **聞かずに進める**: 元に戻せる作業は、確認せずに進める。MCP ツールも必要に応じて使う。チームチャットへの投稿やチケットの更新のような外部への操作も、元に戻せるものは同じ扱いにする。
- **必ず止まる**: 元に戻せない操作の前では止まり、確認を取る。共有ブランチへの force-push、デプロイ、データの削除、顧客へのメッセージがこれに当たる。
- **任されたら続ける**: 「止まらないで」「もう寝る」「終わるまで回して」「全部任せる」と言われたら、元に戻せない操作を除き、止まらずに進める。
- **No と言ってよい**: やるべきか聞かれたとき、作業の追加を勧められたとき、やり方を示されたときは、自分の本当の判断を返す。価値が無いなら断り、間違っていれば反論する。同意を前提にしない。

## プレイブック

- **investigation**: コードを変えずに答えを出す依頼に使う。対象は、仕組み (X はどう動くか)、理由 (なぜこうなっているか)、正しさ (本当に合っているか)、選択 (どちらにするべきか)、失敗の原因 (なぜ CI が落ちたか)。依頼の例は「〜を調べて」「これ確認して」「解説して」「なにこれ」「どう思う？」。
- **autonomous-run**: 長いタスクを、終了条件を満たすまで止まらずに進める依頼に使う。対象は、席を外す間に任せる作業や、確かめられる完了条件まで繰り返す作業。依頼の例は「終わるまで回して」「テストが通るまで続けて」「もう寝るので進めておいて」。
