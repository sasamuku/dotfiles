# Session pickup

**再開点に責任を持つ。前の記録を読み、やり直さない。** 信頼するのは前の判断 (方針、順序、決めたこと) で、成果物についての主張 (テストが通った、merge した) は実物で確かめる。

1. 前の記録を見つける。Issue の作業記録コメントと Epic の一覧、push 済みのブランチと PR、ローカルの `.sasamuku/*.tsv`。記録が複数あれば、最終行が「完了」でないものを対象にし、それも複数なら利用者に聞く。無ければ会話の記録 (Claude Code は `~/.claude/projects/<slug>/*.jsonl` で、slug は今の作業ディレクトリの絶対パスの英数字以外を `-` にしたもので、完全に一致するディレクトリだけ。Codex は `~/.codex/sessions/`。今の依頼文を含むものは今のセッション自身なので除く)。長い記録はサブエージェントに読ませ、判断の時系列だけを受け取る。記録が 1 つも無ければ、手順 2 と 4 を git から分かる範囲で行い、分からないこと (目的、終了条件) を分けて報告し、目的を利用者に確かめて止まる (手順 3 と 5 は skip)。
2. 状態を組み立てる。ブランチと worktree、着地したもの (`git log`、base との diff、merge 済みの PR)、残った todo、決めたこと。記録に無いコミットや未コミットの変更があれば、記録と並べて書く。記録に無いこと (中断の理由など) は推測で埋めず、分からないと書く。
3. 引き継いだ主張のうち、成果物で確かめられるもの (テスト、PR の状態) を実物で確かめる。前の自己申告は証拠ではない。確かめる対象はコミット (HEAD) で、未コミットの変更込みの結果は別に添える。過去のコミットは `git archive` で一時ディレクトリに展開して確かめ、リポジトリの状態を変えない。
4. 終わったものと残りを分け、再開点をブランチ名かコミットで名指しする。記録と実物が食い違っていれば、実物で検証が通った最新のコミットを再開点にし、その先にある変更 (記録に無いコミット、未コミットの変更) の扱いは利用者に決めてもらう項目に入れる。終わった再現や検証はやり直さない。
5. 残りを該当するプレイブックに渡す (Issue や Epic を merge まで運ぶなら orchestrate、1 つの終了条件まで回すなら autonomous-run、それ以外の実装は feature)。利用者が報告で止まるように言っていれば、渡す先を名指しするだけで実行しない。このプレイブックはここで終わり、残りはそのプレイブックの手順で進める。

**返信:** 前のエージェントが止まった場所、引き継いだものとやり直したもの、記録と実物の食い違い、再開点、渡すプレイブック、利用者に決めてもらうこと。
