# Refactor

1. 対象の処理と呼び出し元を読み、維持する入出力、エラー、副作用を確認する。変更前に既存テストを実行し、検証が足りなければテストを補うか、実際の操作と出力を記録する。
2. 整理する範囲と変更後の構造を決める。振る舞いの変更は切り分け、途中で見つけた不具合は別件として報告する。
3. 確かめられる単位で構造を変更する。名前や内部インターフェースを変えたら参照元を探し、影響する呼び出しを更新する。公開インターフェースの互換性を保つ。
4. 手順 1 と同じテストや操作で振る舞いが保たれたかを確かめる。差分を読み、整理した箇所の処理を追いやすくなったかを確認する。
5. 依頼にコミットや PR 作成が含まれる場合は、それぞれ **commit** と **create-pr** を使う。

**返信:** 整理した箇所、構造を変えた理由、維持した振る舞いと確かめ方、未確認事項。PR を作った場合はリンクを添える。
