# Investigation

**答えに責任を持つ。調べる道筋を決め、スキルに振り分け、結果を書く。**

Investigation は読み取り専用の依頼である。成果物はコードの変更ではなく、出典付きの説明か推奨である。

1. コードと実行の流れを読む。範囲が広いときは、観点ごとにサブエージェントへ読ませ、要約だけを受け取る。理由や経緯を問う依頼なら、**why** スキルも使う。
2. 説明は「概要 / 主要な概念 / 仕組み / 構成ファイルの場所 / 落とし穴」の順で書く。どちらにするべきかを問う依頼なら、トレードオフの表を付けた推奨にする。

PR は開かない。この調査がコード変更の前段なら、調査結果をユーザーに返して止まる。

**返信:** 調査結果。「本当に大丈夫？」と聞かれたら、理由を添えて自分の本当の判断を書く。前提が誤っていれば反論する。
