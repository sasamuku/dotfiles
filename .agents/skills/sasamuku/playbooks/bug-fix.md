# Bug fix

1. 報告や仕様から期待する結果と症状を整理し、報告と同じ環境・データ・操作で修正前に再現する。再現できなければ、条件を一つずつ変えるか、ログやトレースで失敗時の状態を調べる。
2. 問題が起きる処理をたどり、正常時と結果が分かれる条件をログやテストで確かめる。以前は動いていたなら [why](../../why/SKILL.md) で変更の経緯を調べる。再現できなくても観測記録で原因を特定できれば、根拠を残して進む。証拠が足りなければ、観測した範囲と必要な情報を報告して止まる。
3. 既存のテスト環境で再現できるなら、回帰テストを追加し、修正前に対象の不具合で失敗することを確かめる。追加が難しければ手順 1 の操作と結果を記録する。
4. 確かめた原因を最小の変更で解消し、調査用のログや変更を取り除く。
5. 手順 1 と同じ環境・操作で再確認し、追加した回帰テストと関連する既存テストを実行する。元の環境で試せなければ、代わりに確かめた範囲と元の環境での未確認事項を記録する。
6. 依頼にコミットや PR 作成が含まれる場合は、それぞれ **commit** と **create-pr** を使う。回帰テストを追加し、運用が許せば、修正前に失敗するテストと修正をこの順で別々にコミットする。

**返信:** 症状、原因と根拠、修正内容、同じ操作での修正前後の結果、未確認事項。PR を作った場合はリンクを添える。
