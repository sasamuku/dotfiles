# Autonomous run

**終了条件に責任を持つ。完了を定義し、止まらずにそこまで進める。**

1. 始める前に、終了条件を確かめられる形で書く (例: テストがすべて通る、再現手順で不具合が起きない、対象の PR がすべて merge された)。あわせて記録先を決める。依頼に Issue (番号か URL) があればその Issue、無ければローカルの `.sasamuku/<タスク名>.tsv` にする。Issue を自分で作ったり探したりはしない。
2. 起きる仕組みを決める。Claude Code では `/loop` を使う。CI や merge のように待つイベントがあれば、それを見張るサブエージェントに起こしてもらい、念のため長い間隔の定期チェックも付ける。待つイベントが無ければ、結果を見直す価値が出る間隔で定期的に起きる。`/loop` が無い環境では、時間を指定したシェルコマンドで待つ。
3. 1 回の繰り返しでは、証拠が裏付ける最小の変更だけをする。終了条件に照らして確かめ、前進したらコミットし、効かなかった変更は元に戻す。「効くかもしれない」程度の変更は残さない。
4. 終了条件の達成を妨げるもの (不安定なテスト、壊れた検証の仕組みなど) は、人に聞かずに自分で片付ける。それ以外に気づいた問題は記録に残し、最後に報告する。人に止めて確認するのは、元に戻せない操作、実験では決まらない判断、本当の行き止まりのときだけにする。
5. 判断を記録先に 1 行ずつ残す。
   - 1 行に書くのは、時刻、判断したこと、理由、証拠 (コミット SHA、PR、`path:line`、成果物のパス)、結果 (終了条件が進んだか) である。
   - 書くのは、分岐の選択、単位の完了と検証結果、取り消しとそのきっかけ、行き詰まりで、自明なことは書かない。ループなら 1 回につき 1 行にする。
   - 間違えた行は消さず、正す行を足す。
   - Issue に記録するときは、作業対象の Issue ごとに「作業記録: <目的>」コメントを 1 つだけ作り、そのコメントを更新し続ける。更新はコメント ID を指定して行う (`gh api repos/<owner>/<repo>/issues/comments/<id> -X PATCH -f body=...`)。同じ Issue を続けるときも同じコメントを更新する。まとめを別のコメントで投稿しない。読み手に「ラン」「N 回目」のような作業者側の区切りを見せない。
   - 複数の Issue を扱うときは、各 Issue に記録を置く。親の Epic には、各記録へのリンクと 1 行の状況を並べたコメントを 1 つ置き、更新する。Epic だけを渡されたときは、配下の Sub Issue を作業対象として同じようにする (Sub Issue が無ければ Epic に記録する)。
   - コメントの上に概要、下に判断の表を置く。概要は、これだけ読めば状況が分かるようにする。
     - ステータス: 🟢 進行中 / ⏸️ 人の判断待ち / ✅ 完了 / ⛔ 行き詰まり
     - 終了条件と、その達成状況
     - 現在の課題と、人に求める判断
     - 成果物 (PR、コミット) へのリンク
   - 判断の行を足すたびに、同じ更新で概要も最新にする。表の時刻には日付を入れる。表が長くなったら `<details>` で畳む。
   - ローカルに記録するときは、TSV に 1 行ずつ追記する。同じタスクを続けるときも同じファイルに追記する。
   - 成果を報告する前に記録先を再取得し、作業記録と必要な親 Epic の更新を確認する。未反映なら、その内容と理由を明示する。
6. 終了条件を満たしたら止まる。頭打ちは止まる理由にならない。やり方を変えて押し続ける。終了条件を緩めて達成したことにしない。本当の行き止まりなら、空回りせずに報告する。

**作業記録のテンプレート (Issue ごとのコメント):**

```markdown
## 作業記録: <目的>

**ステータス:** 🟢 進行中（<いま何をしているか>）

**終了条件と達成状況**

| 条件 | 状況 |
|---|---|
| <条件> | ✅ / 🟢 / ⏸️ / ⏳ <補足> |

**課題・判断待ち**

- <課題、人に求める判断。無ければ「なし」>

**成果物**

- <PR やコミットへのリンクと 1 行の説明>

<details>
<summary>判断の記録（N 行）</summary>

| 日時 | 判断 | 理由 | 証拠 | 結果 |
|---|---|---|---|---|
| YYYY-MM-DD HH:MM | <判断> | <理由> | <SHA、PR、path:line> | 前進 / 取り消し / 判断待ち / 完了 |

</details>
```

**Epic の一覧のテンプレート:**

```markdown
## 作業記録の一覧

| Issue | 状況 | 作業記録 |
|---|---|---|
| #<番号> <タイトル> | ✅ / 🟢 / ⏸️ / ⛔ / ⏳ <1 行の状況> | <作業記録コメントの URL> |

最終更新: YYYY-MM-DD HH:MM
```

**返信:** 終了条件、着地したもの、元に戻したもの、終了条件の最終状態、記録先 (記録コメントの URL かファイルのパス)。
