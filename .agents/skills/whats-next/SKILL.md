# What's Next

対象: $ARGUMENTS (省略時は会話で進めている作業)。

## 選ぶ

会話の目的・合意した範囲・完了条件と現在地を確認し、目的の達成に必要な次の行動を選ぶ。実施済みか、前提が整っているか不明な点だけ、成果物・実行結果・関連 issue / PR で確かめる。

今回の作業が全体の一部なら、会話で示された上位目標・計画・親 issue / Epic に照らし、全体の工程と今回の作業の位置づけを確認する。全体計画が不明ならその旨を示し、確認できる依頼範囲と分ける。説明のために未合意の工程を作らない。

- 合意済みの順序と依存関係を優先する。未反映の成果や必要な検証を、事務的な整理より先に扱う。
- main の同期、古い worktree・ブランチの整理、無関係な既存課題などを、一般に望ましいという理由だけで候補にしない。明示的に求められた整理は対象に含める。
- 外部対応やユーザー判断が必要なら、必要な対応・判断と再開条件を示す。待ちの間に進める作業は、今回の目的に必要で独立して実施できるものに限る。
- 判断材料が足りなければ、その確認を次の行動にする。必要な前提を推測で補わない。

## 提案

最初に全体目標と主な工程を短い一覧や矢印で示し、完了・現在地・残りが分かるようにする。並行作業や依存関係を直列の工程に変えず、今回の作業がどの工程に属するかも示す。全体計画が不明なら工程図を作らず、分かる範囲を明記する。

続けて推奨する行動を一つ示し、全体のどの工程を進めるための行動か、「今それをする理由」と「どこまでできれば完了か」を簡潔に添える。着手に必要な前提・判断・承認があれば明記する。

複数示すのは依存関係や並行作業の説明に必要な場合だけとし、優先順を付ける。候補や将来の改善を網羅しない。完了条件を満たしていれば「次の対応は不要」とし、新しい仕事を作らない。

提案だけの依頼で新たな作業を開始しない。提案を合意済みの計画として扱わず、進行中の依頼や既に得た承認も取り消さない。
