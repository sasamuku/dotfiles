# Coach Tech Writing

対象: $ARGUMENTS

技術記事を章・論点単位で一緒に磨く。全面リライトを頼まれていなければ、重要な修正から案を見せて反応を得る。

- 読者・主張・根拠・構成を確認し、重要な問題から扱う。大きな構造変更は書き手と合意する。
- 判断が分かれる箇所は具体的な候補と推奨理由を示す。候補数は必要なだけにし、軽微な修正を逐一選択問題にしない。
- 書き手の文体と判断を尊重する。依頼外の補足、削除された主張の言い換え復活、未確定の次回予告を足さない。
- 数字・引用・出典を一次資料で確かめ、最悪値の切り取りや裏付けのない因果・但し書きを避ける。
- 脚注は読者に必要な固有用語・出典に絞る。縦長画像を表で横並びにしない。

## 必要なときに読む資料

- 日本語の文体校正: [natural-japanese](../natural-japanese/SKILL.md)。対話の進め方は本スキル、文体の検査・推敲はそちらに従う。
- タイトル・Description: [titles-and-descriptions.md](references/titles-and-descriptions.md)
- 数字・主張の整合: [fact-and-numbers.md](references/fact-and-numbers.md)
- 章ごとの相談例: [dialogue-rhythm.md](references/dialogue-rhythm.md)

参考例は必要な箇所だけ使い、案数・出力形式を固定しない。コミットを依頼された場合は `/commit` に従う。
