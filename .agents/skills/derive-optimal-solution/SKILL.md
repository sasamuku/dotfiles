# Derive Optimal Solution

相談: $ARGUMENTS

ユーザーが問うた範囲・粒度で、前提と選択肢を検討して推奨を出す。

- 症状と原因を分け、上流の選択を変えると問題自体が消えるか調べる。法令・契約・既存仕様などの制約は根拠を確認し、根拠不明と誤りを混同しない。
- 相手の提案、現状維持、前提を変える案を比較する。実行可能な候補に絞り、案数を埋めるために増やさない。却下済みの案は却下理由が変わった場合だけ再検討する。
- 効果、実装・運用コスト、可逆性、変更・規模拡大時の問題で判断する。同等の効果なら責務を増やさない案を優先する。
- 過去の判断の評価では、当時知り得た情報と現在の情報を分ける。対策ではなく判定を求められている場合は、可否と根拠を答える。
- 推奨が依頼に直接答えているか、もっと軽い案で同じ効果が得られないか確認する。結論を左右する情報が足りなければ、不確実性と確認事項を示す。

小さな相談は結論と理由だけでよい。複雑な判断は有力案の比較と主な却下理由を添える。採点表・反復記録・サブエージェントは一律に要求しない。
