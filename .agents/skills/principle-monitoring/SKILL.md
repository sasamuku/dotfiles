# Monitoring

監視は、利用者への影響に早く気づき、対応を始めるために置く。通知は受ける人の注意を使うので、数が増えるほど 1 件ずつの重みが下がる。何を通知しないかも、設計のうちである。

ここにはツールに依らない原則を置く。個々のツールの仕様や既定値は変わるので、使うときに公式ドキュメントで確かめる。

## 原則

### 何を見るか

- **症状を先に見る**: 通知の起点は利用者に見える失敗 (エラー、遅さ、止まっていること) にする。CPU 使用率のような原因の指標は、症状を調べる手がかりと、症状が出る前の予兆に使う。原因だけを見ていると、想定していない原因で壊れたときに気づけない。
- **4 つのシグナルから始める**: 遅延、トラフィック、エラー、飽和を見る。遅延は成功と失敗を分け、平均ではなくパーセンタイルで見る。平均が正常でも、一部の利用者は遅い応答を受けている。
- **事業の指標と結び付ける**: 利用者にとって主要な操作を挙げ、その成否に結び付く通知があるかを確かめる。結び付かない通知は、影響の大きさを判断できない。
- **非同期の処理は滞留と失敗を見る**: キューやバッチの失敗は、利用者にエラーを返さないので、利用者が受け取る応答には現れない。処理待ちの長さ、失敗して退避された件数、定期実行が走らなかったことを見る。
- **依存先を分けて見る**: 外部のサービスの遅延とエラーを、自分の症状と区別できるように計測する。区別できないと、依存先の障害を自分の障害として調べ、時間を失う。

### 通知

- **人が動けるものだけを通知する**: 通知は、利用者に影響があり、受けた人に打つ手があるものに絞る。無視してよい通知が混ざると、本物の通知も読まれなくなる。決まった操作で済む対応と、自動で回復するものは、通知せずに自動化に任せる。
- **緊急度で送り先を分ける**: すぐに人が動くもの、営業時間に見ればよいもの、記録だけでよいものを、別の経路に送る。同じ場所に混ぜると、緊急のものが埋もれる。
- **通知の持ち主を決める**: 通知ごとに、対応する人かチームを決める。誰のものか分からない通知は、誰も見なくなる。
- **閾値には根拠を残し、見直す**: 閾値が高すぎると見逃し、低すぎるとノイズになる。なぜその値にしたかを残し、発火の履歴と利用の変化に合わせて直す。
- **件数と率を使い分ける**: エラーの件数は、トラフィックが増えると正常でも閾値を超える。率は、トラフィックが少ないと 1 件で跳ね上がる。トラフィックが多く安定しているなら率を、少ないか波が大きいなら件数を選び、必要なら両方を条件にする。
- **続いたときだけ鳴らす**: 一時的な揺れは、条件が続いた時間で除く。続く時間を長く取るほど、気づくのは遅くなる。
- **周期のある指標に固定の閾値を当てない**: 時間帯や曜日で大きく変わる指標は、固定の閾値だと、鳴りすぎるか見逃すかのどちらかになる。平常の幅から外れたことを条件にする。
- **通知に対応の手がかりを載せる**: 何が起きたか、どこを見ればよいか、手順書がどこにあるかを通知に含める。
- **復旧も知らせる**: 異常が収まったことが分からないと、対応を終えてよいか判断できない。
- **同じ原因の通知をまとめる**: 1 つの障害で多くの通知が鳴ると、どれが根本か分からなくなる。上流の症状にまとめる。

### 監視そのもの

- **監視を監視対象と一緒に止めない**: 計測と通知が監視対象と同じ基盤にあると、同じ障害で止まる。利用者と同じ経路をたどる外形監視を、監視対象の外に持つ。通知の経路も、監視対象が止まったときに届くものにする。
- **データが届かないことを正常と区別する**: データが届かないときの扱いを、指標ごとに決める。常に値が出る指標が途切れたら、それ自体が異常である。
- **通知が届くことを試す**: 通知の経路は作ったときと変更したときに、実際に通知を流して確かめる。設定を読むだけでは、届くかどうかは分からない。
- **秘密情報を流さない**: 監視の基盤は、本体よりも多くの人とサービスが見る。認証情報と個人情報は、送る前に取り除く。

## 適用範囲と例外

監視とアラートを設計するとき、既存の監視を見直すときに当てはまる。監査ログの集約と脅威の検知は principle-aws-architecture に、Terraform での書き方は principle-terraform に従う。SLO の決め方と、障害対応の体制は扱わない。

- PoC や利用者のいない環境では、通知を省いてよい。秘密情報を流さないことは省かない。
- 基準が分からない新しい指標は、ツールの推奨値があればそこから始める。無ければ、通知せずに記録だけを取り、傾向が見えてから閾値を決めてよい。
