# Reflect

今回の会話から、半年後も通用する学びを拾い、それを使ったスキルの修正に変える。成果物はスキルへの差分で、会話の要約ではない。

些細な会話、一度きりの出来事、従ったスキルどおりに動いて済んだ作業には使わない。一度きりは学びではない。

## 1. 記録を見つける

会話の記録 (ハーネスが残す jsonl) を、この作業ディレクトリの分だけ探す。ほかのプロジェクトの記録は開かない。

- Claude Code: `~/.claude/projects/<slug>/<session-id>.jsonl`。slug は作業ディレクトリの絶対パスの英数字以外を `-` にしたもの。
- Codex: `~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl`。1 行目の `payload.cwd` が作業ディレクトリのものだけ。

slug 直下の `*.jsonl` を新しいものから順に読み、この会話の最初の依頼文と、この振り返りの依頼の両方が入っているものを選ぶ (再開した会話は、同じ依頼文で始まる記録が複数ある)。見つからなければ、会話の要点を書いた短い要約で代え、代えたことを返信に書く。振り返る範囲は、振り返りを頼まれる前までの作業とする。

## 2. 3 つの観点で読ませる

サブエージェントを 3 人、1 度に起動し、`references/reviewer.md` の共通部と観点を 1 つずつ渡す。記録のパスを渡し、ファイルの変更は禁じる。要約は、記録が見つからなかったときだけ渡す (要約があると読み手は記録を開かない)。

| 観点 | 拾うもの |
|---|---|
| 判断 | 出来事の下にある原則。間違いと訂正、利用者の好み、設計判断とその理由、手順の詰まり、手で繰り返した作業 |
| 道具 | 次も調べ直すことになる具体的な事実。コマンドとフラグ、設定や版の癖、ファイルの置き場所、再現と計測の方法。利用者が手で渡した文脈のうち、MCP や別のスキルで自分で取れたもの |
| 逆張り | ほかの 2 人が見落とすもの。運よく通った判断、飛ばした検証、呼び出し元への波及、使うべきだったのに使わなかったスキル、暗黙の前提 |

## 3. 選別する

3 人の所見をそろえ、1 つずつ次の基準で通す。通らなかったものは理由を添えて落とす。

- 半年もつか: パス、SHA、版、コードの形が変わっても真か。変わるものは落とす。
- 行動が変わるか: 読む文が増えるだけでなく、次のエージェントが違う動きをするか。
- 使ったスキルか: 直す先はこの会話で開いたスキルだけ。あれば使えたのに起動しなかったスキルは、起動の条件 (description) を直す対象とする。どちらでもなければ落とす。
- すでに書いてあるか: 直す先のスキルを読んでから決める。同じことが分かる場所に書いてあれば、スキルでなく実行の問題として落とす。埋もれていて効いていないなら、書き足さずに置き場所と言い回しを直す。
- 仕組みで強制できるか: lint、スクリプト、hook、型で確かめられるものは、文章にせず仕組みの候補にする。文章は仕組みでは確かめられない判断だけに使う。
- 2 人以上が挙げたものは信頼を高く、1 人だけのものはほかの基準を厳しく見る。
- 新しいスキルは、既存のどれにも居場所が無く、同じ型が繰り返し出るときだけ。

## 4. 見せて、承認を取ってから直す

採用 / 仕組みの候補 / 落としたもの (理由付き) を表にして見せ、採用の行ごとに承認を取る。利用者が会話の中で先送りした判断と重なる行は、落とさずに、重なることを添える。スキルの修正は今後のすべての作業に影響するので、承認なしに書き換えない。

- 直す先は実体のファイル。symlink なら `readlink -f` で解く (`~/.claude/skills/` の下は dotfiles の `.agents/skills/<name>/`)。プロジェクト固有のスキル (verify-<app> など) はそのリポジトリで直す。プラグインのキャッシュは直さない。
- 1 行の追加や言い回しの修正は、その場で直す。節の追加、新しいスキル、description の修正は **customize-agent** に沿って作る。
- 直した文章は **yomiyasu** で推敲する。
- 仕組みの候補は承認を待たずに返信に書く。Issue にするかは利用者が決める。
- コミット、プッシュ、PR は作らない。

**返信:** 直したスキル (パスと 1 行の内容)、新しいスキル、仕組みの候補、落とした所見と理由、記録でなく要約で代えたならその旨。
