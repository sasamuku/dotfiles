# Design system

デザインシステムは製品の目的に沿って組まれた、繰り返し使える部分のまとまりと、それらを作り、共有し、使うための取り決めである。

役割は 3 つある。作り手の意図が、誰が作っても同じ形で現れるようにする。作り直しを減らし、設計と試行に時間を使えるようにする。職種や部門をまたいで、同じものを見て話せる拠り所になる。

## 具体的な構成要素

デザインシステムは一般に次のものを含む。

- 基本原則 (デザイン原則、ブランドの人柄)
- ロゴ
- 色
- タイポグラフィ
- アイコン、イラストレーション
- 余白、レイアウト、角の形、影、動き
- デザイントークン
- コンポーネント
- パターン (画面や操作の型)
- ライティング (用語、文言)
- アクセシビリティの基準
- デザインデータ、コード
- 運用の決まり (更新、貢献)

## 定義と関係

- **基本原則**: この製品にとって良いデザインとは何かを、作る人どうしで合意した基準。製品の目的と気風から始める。ブランドに寄せたものも、設計の進め方に寄せたものもある。
- **基本要素**: 色、タイポグラフィ、アイコン、余白、角の形、動きのように、製品の印象を作るもの。
- **部品**: ボタン、見出し、フォーム、メニューのように、働きを持つ部分。コンポーネントとも呼ぶ。
- **パターン**: 部品の組み合わせ方と、場面ごとの決まり。
- **トークン**: 見た目についての決定に、名前を付けて保存した値。製品はトークンを参照して作るので、値を 1 か所で変えれば、参照しているすべての場所に反映される。
- **共有言語**: 部品やパターンに付けた名前と、その使い方についての合意。作る人どうしが同じ名前で呼ぶ。
- **運用**: これらを作り、取り込み、出し、使い続けるための取り決め。

基本原則はほかの要素を作り、組み合わせるための文法に当たる。一方で、部品やパターンが育つと基本原則も磨かれる。上から下へ一度だけ導くものではなく、互いに直し合う。

## 判断の観点

### 基本原則

- **本物である**: 「シンプル」「使いやすい」はどの製品にも当てはまる。「複雑」「使えない」を掲げる製品は無い。その言葉がこの製品で何を意味するかまで書く。
- **実践できる**: 「シンプルにする」より「要らない部品を置かない」と書く。画面を見て答えられる問いにし、当てはまる実際の画面を例に添える。
- **立場がある**: 何かを選べば、何かを捨てる。ぶつかったときにどちらを優先するかを示す。
- **覚えられる**: 3〜5 個に絞る。誰も思い出せないなら、直す余地がある。
- **製品と一緒に見直す**: 製品の目的から書き始め、製品が変わったら見直す。
- **組を増やしすぎない**: 部門ごとに別の原則を持つと、デザインシステムがばらばらになりやすい。

### 部品とパターン

- **同じ役割のものは 1 つにする**: 同じ働きに別の見た目を作らない。繰り返し出る独自の UI は、部品にする。
- **状態をそろえる**: その部品に当てはまる状態を、漏れなくそろえる (既定、ホバー、フォーカス、無効、エラー、読み込み中、空など)。抜けた状態は、使う側がその場で埋めることになる。
- **アクセシビリティを組み込む**: 使う側の注意に任せない。コントラスト比は WCAG の AA を下限にし、文字は 4.5:1 以上、大きな文字と文字以外の部品は 3:1 以上にする。
- **使い方を添える**: いつ使い、いつ使わないかを、例と一緒に書く。置いてあるだけでは、使い方が伝わらない。

### トークン

- **層を分ける**: 選べる値を並べた層、値に役割を割り当てた層、部品ごとの層の 3 つ。部品の層はほかの層を参照し、できるだけ直書きの値を持たない。
- **役割で名付ける**: 主操作、本文、背景のように、何に使うかで呼ぶ。テーマの切り替えは役割の層の参照先を変えて行う。
- **値を書く場所は 1 つにする**: ほかの形式が要るときは、その 1 つから書き出す。

### 運用

- **製品として扱う**: 一度作って終わる企画ではなく、ほかの製品に仕える製品である。担当と計画を持ち、使う側の声を聞く。
- **取り込む流れを決める**: 新しい要望はシステムに入れるか、その製品だけのものにするかを決める。ほかの製品や画面でも使うものを、システムに入れる。出す周期と、版の付け方も決める。

## 適用範囲と例外

- 規模に合わせる。小さな製品は基本原則と少数のトークンから始める。トークンは役割の層だけにし、運用も軽くする。
- ほかのデザインシステムを基にするときは、色や形など見た目の決まりを、自分の製品の基本原則で定義し直す。

## 出典

- Alla Kholmatova [『Design Systems』](https://www.smashingmagazine.com/design-systems-book/): 定義、役割、基本原則の観点、基本要素と部品の区別、共有言語
- [Material Design 3 のデザイントークン](https://m3.material.io/foundations/design-tokens/overview): トークンの層
- Nathan Curtis [A Design System isn't a Project. It's a Product, Serving Products.](https://medium.com/p/74dcfffef935) と Brad Frost [A Design System Governance Process](https://bradfrost.com/blog/post/a-design-system-governance-process/): 運用
- [デジタル庁デザインシステム「デザインシステムとは」](https://design.digital.go.jp/dads/guidance/design-system/): 役割、アクセシビリティ、見た目の定義し直し
- [WCAG 2.2](https://www.w3.org/TR/WCAG22/): コントラスト比
- [SmartHR Design System](https://smarthr.design/)、[デジタル庁デザインシステム](https://design.digital.go.jp/dads/)、[Spindle](https://spindle.ameba.design/)、[GOV.UK Design System](https://design-system.service.gov.uk/)、[Carbon](https://carbondesignsystem.com/)、[Material Design 3](https://m3.material.io/)、[Atlassian Design System](https://atlassian.design/): 具体的な構成要素
- Kholmatova の原典は、基本要素を知覚パターン、部品を機能パターンと呼ぶ。
- 「同じ役割のものは 1 つにする」「状態をそろえる」「使い方を添える」「値を書く場所は 1 つにする」「規模に合わせる」は、特定の文献に拠らない判断である。
