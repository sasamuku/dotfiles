# Write Final State

## 入力

`$ARGUMENTS`

対象が指定されていればそれを、無ければ**直近の変更で書いた**ドキュメントとコードコメントを対象にする。

## 判定

残すのは、読者が**今後も必要とする情報**。落とすのは、書いた時点でしか意味を持たない経緯。

判定は文の形ではなく**情報の価値**で行う。「A ではなく B」という形そのものが悪いわけではない。

| 落とす | 残す |
|---|---|
| 些末な決定の変遷 (命名・設定値・DB 名・ツールの選択) | 設計上の判断とその根拠 |
| 作業中に一度試して変えたこと | 実装者が知らないと踏む地雷 |
| 「暫定的に」「今のところ」といった、次に読むときには古い注記 | 現在も並存する選択肢との対比 |

### 落とす例

```
✗ 開発用の daku ではなくテスト専用の daku_test を使う
✓ テストの接続先は daku_test
```

`daku` を候補にした経緯は、次に読む人には不要。`daku_test` を使うという事実だけで足りる。

```
✗ 暫定的にインメモリで保持している
✓ インメモリで保持する
```

「暫定」がいつまでを指すのか、読む時点では判断できない。

### 残す例

```
✓ 存在を漏らさないため 403 ではなく 404 を返す
```

403 は今も実在する応答で、なぜ選ばなかったかがセキュリティ上の判断。

```
✓ display: none は行高が揺れるため max-width: 0 で潰す
```

同じ罠を踏ませないための情報。実装者が知らないと再発する。

```
✓ 本文ではなく冒頭 200 文字を返す
```

本文と冒頭は今も両方ある。仕様の対比であって変遷ではない。

## 対象外

| 対象 | 理由 |
|---|---|
| ADR・Design Doc | 意思決定の記録が目的。経緯はそのまま残す |
| commit message・PR 本文 | 変更を述べるのが役割 |
| CHANGELOG | 履歴そのもの |

## 手順

1. 対象のドキュメント・コメントを読む
2. 経緯を含む記述を挙げ、上の判定でそれぞれ落とすか残すか決める
3. 落とすものを書き換える。理由が必要なら、**選んだものの性質**で説明する
4. 判断に迷ったものがあれば、書き換えずにユーザーに提示する
